Integrations

Use Krypton where your agent and your team already work

Coding agents

Any agent that can run a command can use Krypton. Add the rules from Getting started to CLAUDE.md, AGENTS.md or your tool's rules file. Use --json if a hook needs structured output.

Pre-commit and CI

krypton scan . --base origin/main || { echo "Krypton: structure check failed"; exit 1; }

A GitHub Actions job (build the client once and cache it, or keep a built krypton in your image):

name: Krypton
on: pull_request
jobs:
  structure:
    runs-on: ubuntu-latest
    env:
      KRYPTON_SERVER: ${{ secrets.KRYPTON_SERVER }}
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - run: cargo build --release --manifest-path path/to/client/Cargo.toml
      - run: path/to/client/target/release/krypton scan . --base origin/${{ github.base_ref }}

The client sends only the tree of the changed files, so the job needs a route to the Krypton server and nothing else from your repository leaves the runner.

Docker

docker run --rm -v "$PWD:/work" -w /work rust:1 cargo build --release     # in client
docker run --rm -e KRYPTON_SERVER -v "$PWD:/repo:ro" -v krypton_target:/target:ro \
  debian:bookworm-slim /target/release/krypton scan /repo

The hosted demo

The repository includes a small web app that shows what a codebase costs to read and what a refactor could save.

  1. Visitors sign in with GitHub. GitHub does the authenticating and decides which repositories they may read; Krypton keeps no accounts.
  2. The server reads the chosen repository in memory with the visitor's own access, builds the syntax trees, and sends only the trees to the Krypton server. Nothing from the repository is run or stored, and the visitor's GitHub token is forgotten when they sign out or after an hour.
  3. The page shows files, lines, tokens per read, structure score and the hardest functions, then a savings view built from the real size.

The savings use the rates measured on one repository (see Prompt caching), scaled to the visitor's repository, so treat them as estimates. Deployment steps (Docker and Railway) are in dashboard/DEPLOY.md.
