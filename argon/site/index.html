ARGON

Structure scoring for code your agents write. Local, fast, built for JavaScript, TypeScript and Python.

Argon counts branches, nesting depth and bloated functions, then tells your coding agent which files to split before they cost tokens and break things. It is not a linter; run yours alongside it.

Local
No network, no account. One pass over the syntax tree.
Agent-shaped
Plain output for the terminal, JSON for hooks and CI.
Hard to game
Packing code onto one line doesn't lower the score.

Install

pip install .          # from the repo folder; needs Python 3.12+
argon src --top 10

Or with Docker:

docker build -t argon .
docker run --rm -v "$PWD:/repo" argon .

Give your agent the loop

Paste this into CLAUDE.md, AGENTS.md or your tool's rules file:

## Code structure (Argon)
- After editing source files, run: `argon <the files or folders you changed> --top 10`
- If a file is flagged, or a function you wrote shows a `nested` flag, refactor it
  before finishing: early returns, small named helpers, one job per function.
- Do not satisfy Argon by packing code onto fewer lines or by splitting one function
  into many trivial wrappers; the score counts characters and statements, not newlines.
- Re-run Argon after refactoring and report the purity score.

Score only what changed

argon . --base HEAD          # changes since the last commit, new files included
argon . --base origin/main   # everything on this branch
argon src --json             # full result for hooks and CI

Exit code 0 passes, 1 means the purity score fell below 40, 2 is a usage error.

Reading the output

ColumnMeaning
branchesDecisions in the file: if, loops, case, catch, &&, ternaries. Counted like radon and ESLint.
nestingThe same decisions weighted by depth. Three nested ifs score 6, not 3.
depthDeepest nesting. A function gets the nested flag at depth 3 or more.
effEffective lines. Long or multi-statement lines weigh more, so packing doesn't help.
ratingBranches squared times effective lines, divided by distinct outputs. Over 648 the file is flagged.
Purity Score0 to 100 for the whole run.

A flagged file means an agent will spend extra tokens reading it and is more likely to break it. The usual fix is splitting a large function by job, not deleting logic.

Good to know

  • It measures structure, not correctness. It will not catch a bug.
  • Files over 1 MB, lines over 5,000 characters, or one node with over 50,000 children are flagged oversize and not parsed. Minified bundles land here.
  • Inside a git repo, anything .gitignore ignores is skipped.
