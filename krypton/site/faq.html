FAQ

Frequently asked questions

Is Krypton a linter?

No. It measures structural weight, how hard code is to read, edit and pay for in tokens. It does not check style or correctness. Run your linter and tests too.

Does it send my code anywhere?

The command-line tool runs locally and makes no network calls. The hosted demo reads a repository you choose in memory, scores it and discards it; nothing is stored or run.

Which languages does it support?

JavaScript, TypeScript (including JSX and TSX) and Python.

How is the score calculated?

It is modeled after radon: every decision in a function (a condition, loop, case, catch, boolean operator or ternary) is counted the way radon counts it. Krypton adds where each decision sits, using a depth-first walk of the syntax tree that tracks how deeply decisions are nested, so a function with three decisions stacked three deep scores worse than one with three side by side. The exact weights and the rating formula are not published. How the score is calculated walks through an example.

Why was my file flagged?

The report lists the reason, and hints name the block most worth extracting. Run krypton path/to/file --top 10 to see the heaviest functions.

Can I make it less strict while I clean up?

Yes: --level relaxed, or --base origin/main to score only what changed on your branch.

Will it find bugs?

No. Heavy code is more likely to hide bugs, but Krypton only measures structure.

What happens to minified or generated files?

Generated and vendored paths are skipped, including minified files, bundles and copies of libraries such as bootstrap or jQuery that were committed into the repository, so they are not scored as your code. Files that are too large or have extremely long lines are not analyzed; they are left out of the score and listed, with the setting that would include them.

Does it work with my coding agent?

Any agent that can run a command can use it. See Integrations.

How much will the file ordering save me?

It depends on your repository. On garth it made the same prompts 35% cheaper. Across 20 open-source repositories it beat alphabetical order on 12 and lost on 7, with a typical gain of about 4 points of cache reuse. It helps when recently active files stay active. You can predict your own result for free; see Prompt caching.

Does cleaning up code make my agents cheaper?

In our tests, only a little and unevenly: later changes were about 17% cheaper on average over six runs, but about 6% for the typical run, and the cleanup costs money once. Cleaned code was not more correct, and an unguarded tangle did not make agents' later changes steadily dearer within 20 revisions. The reasons to clean up are the people who read the code and future risk. See the results.

Should I add Krypton to CI?

For code health, yes: in our 20-revision test a gate held garth's worst function near 12 times over the limit against about 1,900 times without it, with every revision still correct. It did not save money; the gated runs cost about 62% more because of the fix rounds. See the CI gate results.

Does it work on Windows?

Yes. It is a Python package; you need Python 3.12 or newer.
