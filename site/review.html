Review

A person approves what the agent could not simplify

An agent refactoring toward a better score sometimes gets stuck: three tries later a function is barely better. Krypton keeps a log of every try, says which functions are stuck, and puts any earlier try back. Your coding agent turns that into a small page on your own computer where you approve the best try or send it back, before anything goes to GitHub.

The review step

  1. Log each run. The agent runs krypton scan . --log --ticket "what it is fixing" before it starts (run 0) and after each change. Each run records the purity score and how far over the limit every function is, under its real name, in .krypton/runs.jsonl, and saves the state of the files as a patch.
  2. Ask what is stuck. krypton review --json lists the functions that, after the start and three runs, are still over the limit and never got more than 10% better than where they started, with the score at every run and the best run.
  3. Show a person. The agent builds one local page from that data and your themes.md. For each stuck function you choose Approve best or Send back.
  4. Carry on. Approved: krypton restore --run N puts the best run's files back and the agent continues to push and open the pull request. Sent back: the agent tries that function again.

Nothing in this step leaves your machine.

Commands

scan --log

krypton scan . --log --ticket "fix discount rounding"

Scores as usual, then adds the run to the log and saves its attempt. --ticket names the piece of work; the first run of a ticket is run 0. It needs a git repository with a first commit and must be run from the repository's top folder. The .krypton/ folder ignores itself (it holds a .gitignore of its own), so the log and the saved code cannot be committed by accident.

review

krypton review [REPO] [--ticket TEXT] [--json]

Without --json it prints a short summary. With it:

{
  "ticket": "fix discount rounding",
  "runs": [ {"run": 0, "purity": 71}, {"run": 1, "purity": 72}, ... ],
  "purity": { "start": 71, "now": 72, "if_approved": 74 },
  "restore_run": 2,
  "needs_review": true,
  "improved": 12,
  "stuck": [ { "file": "checkout.py", "function": "apply_discount",
               "ratings": [46.0, 45.0, 43.0, 44.0], "best_run": 2, "best": 43.0 } ],
  "note": null
}

A score is how many times the limit a function is at (1× is the most a function may have). restore_run is the run with the highest purity, and if_approved is the purity at that run.

restore

krypton restore --run N [REPO] [--ticket TEXT] [--dry-run] [--force]

Puts the files back to how they were at run N. It refuses if the files have changed since the last logged run, so nothing unsaved is lost; --force skips that check after saving what is there to .krypton/attempts/before-restore.patch. --dry-run lists the files it would change and touches nothing. If a patch does not apply cleanly, everything is put back and the reason is printed. No commits or branches are made.

comment, badge, and scan --summary

krypton scan . --summary head.json
krypton comment base.json head.json [--badge FILE] [--fail-if-worse]
krypton badge head.json purity.json

--summary writes the run's scores to a file and does not fail on a flagged review. comment prints the pull request comment as markdown; badge writes the README badge as a shields.io endpoint file.

The review page

Krypton does not build the page and does not read themes.md. The agent you already use builds it, following agent/review-brief.md: the same outline every time (the ticket, purity now and if you approve, one card per stuck function with its scores and two buttons, and a footer), styled the way themes.md describes in your own words. On GitHub

The action in this repository's root scores a pull request against its base, keeps one comment up to date, and refreshes a badge when you push.

name: Krypton
on:
  pull_request:
  push:
    branches: [main]
permissions:
  contents: write
  pull-requests: write
jobs:
  structure:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - uses: pinklamb/Krypton@main
        with:
          server: ${{ secrets.KRYPTON_SERVER }}
          fail-on-worse: "false"

The comment looks like this, and is edited in place on every push:

### Krypton · ▲ 71% → 74% (+3)

| | Before | After |
|---|---|---|
| Purity | 71% | 74% |
| Over the limit | 14 | 12 |

**2 functions got worse**
- `billing.py · apply_discount` 40× → 44×
- `auth.ts · refresh_session` under the limit → 2×

For the badge, add this to your README with your own name and repository:

![Krypton](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/OWNER/REPO/krypton-badge/purity.json)

The badge file is read from a public address, so it shows only on public repositories. For a private repository, commit a badge image instead.

Limits

  • Restoring is for the whole working tree, not one function. An attempt is the state of all changed files at that run, so putting back run 2 puts back everything as it was at run 2. restore_run picks the run with the best purity overall; a function whose own best run was a different one is shown as such, but one restore cannot give two functions two different runs.
  • Attempts cover tracked files and new files that are not ignored. Ignored files are not saved. Attempts hold your code as patches, so keep .krypton/ out of anything you share.
  • A function counts as stuck only after the start and three runs. With fewer, review says so in note.
  • The wording bands in the preview ("very hard to read") are only examples; the commands report numbers.
