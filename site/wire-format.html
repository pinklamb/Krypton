Wire format

Wire format, version 1

The body of POST /v1/score. A client reads source on the user's machine and writes this; the server never receives the source.

Status. Version 1 is the format the server speaks; a server answers 426 to any other wire_version.

The request

{
  "wire_version": 1,
  "client": { "name": "my-client", "version": "0.1.0" },
  "options": { "level": "standard", "detail": "summary", "config": {} },
  "files": [ /* one entry per file, see below */ ]
}
FieldTypeMeaning
wire_versionintegerMust be 1.
clientobjectname (up to 64 characters) and version (up to 32). Used for support.
options.levelstringrelaxed, standard (default) or strict: how tight the flag limits are.
options.detailstringsummary (default) or full. full is refused unless the server was started to allow it.
options.configobjectOverrides for file selection and conventions only. See capabilities for the allowed keys. Anything else is refused.
filesarrayAt least one file. Paths must be unique.

Unknown keys anywhere in the body are refused, so a typo cannot silently change a score.

The tree

A tree is flat parallel arrays in depth-first pre-order, one entry per node, never nested objects: nested JSON hits parser depth limits on deeply nested code, and arrays are smaller and compress well. Every node is present, punctuation and comments included.

ArrayEntry for node i
nThe number of nodes. Node 0 is the root.
kinds, kindA string table of grammar kinds, and each node's index into it.
fields, fieldA string table of roles (name, body, ...), and each node's role in its parent, or -1.
parentThe parent's index, -1 for the root. Always an earlier node (parent[i] < i).
flagsA bit mask: 1 named, 2 extra (a comment), 4 syntax error, 8 missing (inserted by the parser).
start_line, end_line0-based lines.
start_col, end_colColumns, in characters.
start_index, end_indexCharacter offsets from the start of the file; the end is exclusive.
maskSparse map, node index to a stand-in that keeps one fact.
digestSparse map, node index to a 16-hex fingerprint.

All offsets are characters, not bytes. All arrays have exactly n entries.

What carries text

An unnamed token (a keyword or punctuation) needs none: its kind is its text. For named nodes, the client sends one of three stand-ins and never the text:

NodeSent asWhy
A name: identifier, property, type name, object key, a declaration's namedigest: 16 hex characters of the SHA-256 of the textThe server compares names, never reads them. The client's names book turns fingerprints back into names in the answer.
An expression the engine only compares: a returned or yielded value, an expression body, the object a method is called on, the class a new builds, a decorator's namedigest, of the text with whitespace runs collapsed to one space and trimmedTwo outputs are the same exactly when their fingerprints are.
A match patternmask: _ if exactly _, else ?The engine asks only whether it is a catch-all.
A dotted namemask: each part becomes n, so a.b.c is n.n.nThe engine asks only whether there is a dot.

If the engine needs the text of a node the client sent no stand-in for, the answer is a clear 422 invalid_tree naming the node, never a guess.

Line shapes

lines has one entry per physical line: [length, runs], where length is the line's length in characters (trailing blanks included) and runs is a list of [start, end) ranges of visible, non-blank characters. It carries line lengths and indentation exactly, with no identifiers or strings. cr lists the 0-based lines that ended with a carriage return, and final_newline says whether the text ended with a newline. The server rebuilds a same-shape skeleton from this, so every line-based rule gives the same answer it would on the real text.

Facts from the client

Some facts need real text and are worked out on the client: whether the file carries a generated marker, whether it looks like a bundled library, how long its longest line is, which lines hold a waiver and the digest of its reason, which imports resolve to which files in the request, and which lines changed. They arrive as the plain fields above.

Rules a request must meet

  • All tree arrays have length n; parent[i] < i for every node except the root; every kind and field index points into its table.
  • Every range lies inside the file the lines describe, a node's range lies inside its parent's, and siblings do not overlap.
  • Waiver and carriage-return line numbers are lines of the file; each run lies inside its line, in order, not overlapping.
  • Masks are short, digests are exactly 16 hex characters, and the number of imports and candidates is bounded.

A request that breaks a rule gets 422 with the JSON path of the first problem. The size limits are in the API reference.
