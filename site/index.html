Don’t wait for a CI gate to tell you an agent broke your architecture.

    
Linters and GitHub Actions run after the work is done, and leave you reviewing messy diffs. Krypton closes the loop on your machine: your agent writes a change, Krypton scores it across the full syntax tree, and the agent refactors the hotspots before it opens a clean pull request.

Know which functions kept your agent looping.

      
Every scored run is written to .krypton/runs.jsonl: the ticket, the score, and each function still over the limit, with how many times over it is. krypton review reads it and names the functions that were still stuck after your retry limit, and which run came closest.

    
# .krypton/runs.jsonl
{"run":0,"ticket":"fix discount rounding","purity":71,"functions":{"checkout.py::apply_discount":46.0}}
{"run":1,"ticket":"fix discount rounding","purity":71,"functions":{"checkout.py::apply_discount":45.0}}
{"run":2,"ticket":"fix discount rounding","purity":71,"functions":{"checkout.py::apply_discount":43.0}}
{"run":3,"ticket":"fix discount rounding","purity":71,"functions":{"checkout.py::apply_discount":44.0}}

$ krypton review
Ticket: fix discount rounding
Stuck after 3 runs: 1
  checkout.py · apply_discount: 46× → 45× → 43× → 44× (best: run 2)
# example values, trimmed; each log line also records the time

Your source code never leaves your machine.

      
Krypton parses your code on your computer and swaps every function, variable and file name for a keyed hash. Only the structure is sent to be scored. The key is made fresh for every scan and stays with you.

    
$ krypton wire folder/filename.py
# prints exactly what would be sent for that file
$ krypton scan . --base origin/main
# scores only what this branch changed

  


  

    

      
Your agent cleans up after itself.
Run krypton setup to set a target score and a cap on retries. Your agent scans after each change, untangles deep nesting and branching hotspots by itself, and only asks for your sign-off when a function hits your retry limit. Answer the questions in the terminal, or click your settings on a local dashboard.
Krypton suggests a target from where you are: if your codebase scores 56, it suggests 70, and you can pick your own. Only new tickets are held to it, so the code they touch gets cleaner while old code never blocks a merge. Run setup again as the score climbs and the suggestion climbs with it.
