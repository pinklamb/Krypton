Integrations

Use Krypton where your agent and your team already work

Coding agents

Any agent that can run a command can use Krypton. Add the rules from Getting started to CLAUDE.md, AGENTS.md or your tool's rules file, and pass --history so each iteration is compared with the last. Use --json if a hook needs structured output.

Pre-commit and CI

krypton . --base origin/main --top 0 || { echo "Krypton: structure check failed"; exit 1; }

A GitHub Actions job:

name: Krypton
on: pull_request
jobs:
  structure:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - uses: actions/setup-python@v5
        with: { python-version: "3.12" }
      - run: pip install path/to/krypton   # wherever Krypton lives for you
      - run: krypton . --base origin/${{ github.base_ref }} --top 10

The summary_markdown field of the JSON output is formatted as a pull request comment.

Docker

docker build -t krypton argon
docker run --rm -v "$PWD:/repo" krypton .

The hosted demo

The repository includes a small web app that shows what a codebase costs to read and what a refactor could save.

  1. Visitors sign in with GitHub and pick one of their repositories.
  2. The server reads it in memory with the visitor's own access, scores the Python, JavaScript and TypeScript files, and discards it. Nothing from the repository is run or stored.
  3. The page shows files, lines, tokens per read, structure score and the hardest functions, then a savings view built from the real size.

The savings use the rates measured on one repository (see Prompt caching), scaled to the visitor's repository, so treat them as estimates. Deployment steps (Docker and Railway) are in dashboard/DEPLOY.md.
