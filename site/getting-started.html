Getting started

From install to your first scan in five minutes

Krypton has two parts. A small client on your machine parses your code into a syntax tree. A Krypton server scores it and sends back the review.

1. Get the client

The client is one program, krypton, written in Rust. Build it with Docker (nothing else to install):

$ cd client
$ docker run --rm -v "$PWD:/work" -w /work rust:1 cargo build --release
# the program is target/release/krypton

Or, if you have Rust installed, cargo build --release in the client folder. Tell it where the server is once:

$ export KRYPTON_SERVER=https://YOUR-SERVER

There are no accounts or keys. The server answers anyone, and limits each address to a few requests a minute.

2. Run your first scan

$ krypton scan .
$ krypton scan src --level relaxed --names

Give it a folder. It reads every .py .js .jsx .mjs .cjs .ts .tsx .mts .cts file, skipping node_modules, dist, .git and the like, and builds the tree of each. --names puts your real function names back into the review locally: the server only ever saw fingerprints of them.

3. Read the report

The review ranks the heaviest functions, says why each is flagged, names the block most worth moving into its own function, and ends with a purity score from 0 to 100 for the whole run. Higher is lighter.

A flagged file means an agent will spend extra tokens reading it and is more likely to break it. The fix is almost always to split a large function by job, not to delete logic. Add --json for the result as JSON, or --save FILE to keep the server's whole answer.

Exit codes

  • 0: fine.
  • 1: the review failed (the purity score fell below the failure line), or the server or a file could not be reached or read. The message says which.
  • 2: usage error, such as a missing folder or a bad option.

4. Score only what changed

$ krypton scan . --base HEAD          # lines changed since the last commit, including new files
$ krypton scan . --base origin/main   # everything on this branch

Only the files and lines changed since that git ref are scored, so old code in the same file does not blame the agent.

5. Put it in your agent's loop

Paste this into CLAUDE.md, AGENTS.md or your tool's rules file:

## Code structure (Krypton)
- After editing source files, run: `krypton scan . --base HEAD --names`
- If a file is flagged, or a function you wrote appears in the review, refactor it
  before finishing: early returns, small named helpers, one job per function.
- Do not satisfy Krypton by packing code onto fewer lines or by splitting one function into
  many trivial wrappers.
- Re-run Krypton after refactoring and report the purity score.

A typical session: the agent edits, runs krypton scan, reads the flagged functions, refactors, and runs it again.
