2 · Does it hold on other repositories?

20 open-source repositories, 12 replayed commits each, predicted reuse for each file order (the prediction matched live Claude runs within about a point on garth and pluggy)

Krypton's order beat alphabetical on 12 of 20, tied on 1 and lost on 7. Average reuse: 31% against 25% alphabetical and 26% reverse; typical gain 4 points. garth is one of the best cases.

Show all 20 repositories

Live replays on two more repositories: pluggy, Krypton's order 4% reused against 22% alphabetical and 25% reverse (the reverse run stopped early at the spending cap); MCP filesystem server (TypeScript, 13 files, 12 commits), Krypton's order 38% against 31% alphabetical, predicted 42% and 31% (the run stopped at the spending cap during the alphabetical order, and reverse did not run). Re-weighting the change history and picking a rule per repository did not improve held-out results, so the ordering is unchanged.

5 · Payback: refactor once, then iterate

one-time cleanup $0.476 · $0.0429 per change on the original · $0.0356 after the standard cleanup (−$0.0073, −16.9%) · average of 6 runs

66 changes to break even on the average of six runs. After that, every change costs 16.9% less ($0.0073 of $0.0429), though the typical run saved about 6%.

Run by run the payback ranged from 18 changes to never: the savings were 44%, 7%, 5%, 25%, 0%, 1%. Six runs on one project (three with unrelated tickets, three revising one feature), so treat 66 as an estimate.

Cumulative dollars saved vs. not cleaning up

Return on total spend includes the one-time refactor, so it approaches 16.9% as changes accumulate.

6 · Rebuild garth to a score of 75, then measure

An agent used Krypton's own output to refactor the worst function first, re-scoring after each step, until garth's structure score passed 75. It stopped at 81.

Cost row: one run of five later feature revisions on the rebuilt code against the three no-cleanup runs ($0.177 on average, range $0.163 to $0.191). One run is a data point, not a result.

7 · A Krypton CI gate over 20 revisions

One feature grew over 20 sequential agent revisions, three chains per setup. Gate: after each ticket the harness scored the code with Krypton and sent an agent back to fix any touched function over the limit (up to two rounds).

The gate kept the code far healthier and cost about 62% more per chain. Cost per revision did not keep rising with the tangle in the plain chains: about 30% up over the first ten revisions, then flat.

11 · Method and formulas

The ordering only arranges files; it never changes a complexity score.

  • Volatility orderfiles are sent from least to most frequently changed, using Krypton's ordering algorithm over the repository's change history, so the stable part of the prompt stays at the front.
  • Cached sharecached_tokens ÷ prompt_tokens, read from the provider's usage fields, replayed commits 1–12 (turn 0 is a cold start and can never hit).
  • Predicted sharelongest common prefix of two consecutive prompts ÷ prompt length, Matched the live Claude result within about 2 points.
  • Bill ratio1 − (1 − k) · h, where h is the reused share of each request and k is the cached-read price as a fraction of the normal input price.
  • Per-change savingdollars an agent spent on five change tickets, original vs after the standard cleanup, over six runs: $0.0073 less of about $0.0429 per change (16.9%). The runs saved 44%, 7%, 5%, 25%, 0%, 1%.
  • Paybackone-time cleanup cost ÷ per-change saving = $0.476 ÷ $0.0073 ≈ 66 change tasks. Net dollars saved after n changes = 0.0073 · n − 0.476; return on total spend = that ÷ (0.0429 · n).

Summary

  • CachingOn garth, Krypton's file order kept 71% of prompt tokens cached, against 47% alphabetical and 0% reverse, so the 13-turn replay cost $0.51 against $0.79 and $1.30. That is a best case: across 20 repositories it beat alphabetical on 12, tied on 1 and lost on 7, and on a second live replay (pluggy) it reused 4% against 22% and 25%.
  • RefactorLogic-complexity flags went from 9 to 0 with all 163 tests passing; the control agent left 8 of 9.
  • Payback66 change tasks repay the one-time cleanup ($0.48) on the average of six runs. After that, every change costs 16.9% less on average (about 6% for the typical run).
  • CI gateOver 20 agent revisions a gate kept the worst function near 12× the limit against about 1,900×, and the structure score at 72 against 55, for about 62% more cost per run.
  • AI against the restIn garth and the MCP reference servers, AI-assisted functions are not more tangled per unit of size; they are smaller.
  • CostThe refactor used 2.4× the tokens of a no-Krypton refactor and left the code the same size.

One repo (garth), one cache model; the payback figures come from 6 runs: read them as estimates.
